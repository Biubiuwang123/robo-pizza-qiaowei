Chapter 2 · AWS Certificate Manager

The website has to be the real one

Before the teacher types a password, the browser checks a certificate that says "this really is the school's site." This chapter shows how that certificate is issued, renewed, priced, and what it looks like on this very page.

Explain it three ways How it's priced Alternatives See it run

Explain it three ways

For an executive

ACM gives a website its padlock at no cost and renews it automatically. An expired certificate takes a site offline for every visitor at once, so removing the renewal chore removes a whole class of outage. You only pay if you need the certificate somewhere outside AWS.

For a product manager

The value is the lifecycle, not the certificate. The industry is cutting the maximum life of public certificates from 398 days to 47 by 2029, so renewal goes from a yearly task to a near-monthly one. With ACM you prove domain control once with a DNS record; as long as that record stays in place and the certificate is in use, ACM renews it 45 days before it expires.

The trade-off: the free certificate's private key never leaves AWS, so it only works on services ACM integrates with, such as CloudFront and load balancers. Running your own servers means a paid option: exportable certificates or ACME.

For an engineer
  1. RequestCertificate with DNS validation returns a CNAME record. Publishing it proves control of the name.
  2. ACM issues the certificate (198-day validity) and keeps the private key. This site asked for an ECDSA P-256 key, signed with ecdsa-with-SHA256.
  3. CloudFront references it in ViewerCertificate (SNI, minimum TLSv1.2_2021). For CloudFront, the certificate must be in us-east-1.
  4. The certificate is written to public Certificate Transparency logs, so anyone can audit what was issued for the domain.
  5. At 45 days before expiry, ACM checks that the CNAME still resolves and the certificate is in use, then renews it in place. No redeploy.

How it's priced

Three ways to get a public certificate from ACM, with public list prices:

OptionWhere it worksPrice
Public certificate (non-exportable)ACM-integrated services, e.g. CloudFront, load balancersNo cost
Exportable public certificateAnywhere: you get the private key$7.00 per domain name, $79.00 per wildcard, charged at issuance and at each renewal
ACME certificate (max 45 days)Anywhere, renewed by an ACME client$1.00 per domain name for the first 1,000 a month, then $0.50, then $0.25 above 4,000; wildcards $5.00, then $2.50 above 500

Worked example: a made-up pizza shop with 3 hostnames

  • Behind CloudFront: 3 non-exportable certificates = $0 a year.
  • On its own servers, exportable: a 198-day certificate renewed 45 days early is charged about 2.4 times a year. 3 × $7.00 × 2.4 ≈ $50 a year.
  • On its own servers, ACME, rotated monthly: 3 × $1.00 × 12 = $36 a year, with shorter-lived certificates as a bonus.

This site uses the first option. Its certificate costs $0, tracked in the project's cost ledger.

Alternatives

Other ways to get and renew a public TLS certificate:

OptionWhat it isFits when
Let's EncryptFree, nonprofit certificate authority. 90-day certificates by default, 6-day ones by opt-in.You run your own servers and an ACME client to renew.
cert-managerOpen-source Kubernetes controller that requests certificates (often via ACME) and renews them before they expire.Your workloads live in Kubernetes.
Cloudflare Universal SSLFree edge certificates for sites served through Cloudflare.Your traffic already goes through Cloudflare.
Google Cloud Certificate ManagerGoogle-managed certificates for Google Cloud load balancers.You serve from Google Cloud.
Azure App Service managed certificateFree certificate for custom domains on App Service.You host on Azure App Service.

They share a pattern: the certificate is cheap or free, and what you are really choosing is who automates renewal and where the private key lives.

See it run: this page's own certificate

Click the padlock in your address bar. The certificate you see was issued by ACM for robo.qiaowei.wang on 11 October 2026. Here is what it looks like from a terminal.

1. Proving domain control: the DNS validation record

$ dig +short CNAME _f85a0ec706182a627b3a1f15fd94c27d.robo.qiaowei.wang
_284bc84dbad0eade587e4497934e3d13.wzccmgtwzk.acm-validations.aws.

ACM asked for this record. It stays in place so renewals validate on their own.

2. The certificate chain the browser verifies

$ openssl s_client -connect robo.qiaowei.wang:443 -servername robo.qiaowei.wang -showcerts
 0 s:CN=robo.qiaowei.wang
   i:C=US, O=Amazon, CN=Amazon ECDSA 256 M04
 1 s:C=US, O=Amazon, CN=Amazon ECDSA 256 M04
   i:C=US, O=Amazon, CN=Amazon Root CA 3
 2 s:C=US, O=Amazon, CN=Amazon Root CA 3
   i:C=US, ST=Arizona, L=Scottsdale, O=Starfield Technologies, Inc., CN=Starfield Services Root Certificate Authority - G2

Leaf → intermediate → root. Each line s: is the subject; i: is who signed it.

3. The leaf certificate

$ openssl x509 -noout -text   # key lines only
Public Key Algorithm: id-ecPublicKey   NIST CURVE: P-256
Signature Algorithm:  ecdsa-with-SHA256
Not Before: Oct 11 00:00:00 2026 GMT
Not After : Apr 26 23:59:59 2027 GMT     # 198 days
Subject Alternative Name: DNS:robo.qiaowei.wang
